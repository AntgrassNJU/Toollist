# 清单 · 问题求解（第一论域）

一个给自己用的待办清单：三个标签页（**A 待办作业 / B 待实现 idea / C 学习规划**），
数据存在你自己 Supabase 项目里，电脑和手机自动同步，手机浏览器"添加到主屏幕"后像一个 App。

```
index.html     整个应用（界面 + 逻辑，就这一个文件）
supabase.sql   数据库初始化脚本（建表 + 行级安全策略）
README.md      本文件
```

---

## 1. 建数据库

1. 打开 [supabase.com](https://supabase.com)，新建一个项目（区域选最近的即可，免费额度足够）。
2. 左侧 **SQL Editor → New query**，把 `supabase.sql` **全部内容**粘进去，点 **Run**。
3. 左下角应提示 Success。可以再执行一次文件末尾那句自检 SQL，看到 `rowsecurity = true` 就对了。

## 2. 建一个"只给这个工具用"的账号

**不要用你自己常用的、或者绑定了别的东西的账号。** 单独建一个：

1. 左侧 **Authentication → Users → Add user → Create new user**。
2. 填一个邮箱和密码（邮箱不必真实可用，你自己别忘就行），
   **勾上 Auto Confirm User**（否则没验证邮箱登不进去）。
3. 这个邮箱密码就是待会儿登录要填的东西。

## 3. 拿到公开 key，填进 index.html

1. 左侧 **Settings → API**（新版可能叫 **Project Settings → Data API**）。
2. 复制两样东西：
   - **Project URL**：形如 `https://abcdefgh.supabase.co`
   - **anon public** key：以 `eyJ` 开头的长字符串
3. 打开 `index.html`，在最顶端找到这两行填进去：

```js
const SUPABASE_URL      = "https://abcdefgh.supabase.co";
const SUPABASE_ANON_KEY = "eyJhbGciOi...";
```

> **这两个值可以放心提交到 GitHub。**
> `anon key` 本来就是"公开密钥"，设计上就给浏览器用。
> 你的数据由数据库里的行级安全策略守着（`auth.uid() = user_id`），
> 别人拿着这个 key 也读不到你任何一条待办。
> **绝对不能进仓库的**：你的登录密码、以及登录后浏览器里那个访问令牌（`eyJ...` 的长串）。
> 本仓库里不含任何令牌；`index.html` 里出现 `eyJ` 只能是 anon key 那一次，属正常。

## 4. 放到一个 https 网址上（GitHub Pages，约 3 分钟）

**为什么不能直接双击打开本地文件**：浏览器对 `file://` 打开的页面有安全限制，
它发出的跨域请求会被拦掉，同步用不了。所以必须挂在 https 上。

1. GitHub 上新建一个仓库，比如 `todo`，选 **Public**（Pages 免费版只给公开仓库，没关系——代码里没有秘密）。
2. 把 `index.html`（`supabase.sql`、`README.md` 也一起，便于以后再看）传上去。
3. 仓库 **Settings → Pages → Source** 选 `Deploy from a branch`，
   Branch 选 `main` / 目录选 `/ (root)`，Save。
4. 等 1 分钟左右，访问 `https://<你的用户名>.github.io/todo/`。

### 提交前的自查（重要）

在 GitHub 上打开你上传的 `index.html`，用浏览器的"查找"搜 `eyJ`。
**只应该出现 1 次**，就是 `SUPABASE_ANON_KEY` 那一行。
如果出现多次、或者你自己都不确定，说明令牌混进去了 —— 立刻回到 Supabase
**Authentication → Users** 把那台账号的密码改掉（令牌随之作废），再检查一遍文件。

## 5. 手机（Android）上添加

1. 用 **Chrome** 打开 `https://<你的用户名>.github.io/todo/`。
2. 填一次邮箱密码，登录。
3. 右上角 **⋮ → 添加到主屏幕 → 安装/添加**。
4. 之后再打开就用桌面图标，全屏显示，和 App 一样。

电脑上打开同一个网址、填同一组邮箱密码，两边就是同一份数据了。

## 6. 数据结构

每一条任务在数据库里是一行，字段就是你要的那几项：

| 字段 | 含义 |
| --- | --- |
| `id` | 唯一标识。**由客户端生成**（uuid），不是数据库自增 |
| `user_id` | 归属者。行级安全策略就靠它判断"这是谁的数据" |
| `category` | `'A'` / `'B'` / `'C'`，决定它出现在哪个标签页 |
| `title` | 任务名 |
| `note` | 任务备注 |
| `due_at` | DDL。可空——`null` 表示"无期限"，只有 A 类会用到 |
| `done` | 完成状态 |
| `pinned` | 置顶（B 类用来把重要的 idea 钉在最上面） |
| `created_at` | 创建日期 |
| `updated_at` | 最后修改时间，由数据库触发器自动维护，前端不用管 |

**为什么 id 让客户端生成**：如果让数据库分配 id，那就得先上传、拿到返回的 id，
才能把这行显示出来——断网时就插不了卡片。客户端先定 id，本地立刻显示、上传只是"告诉服务器一声"，
这是"离线优先"设计的通用套路。

## 7. 同步是怎么工作的（一句话版）

本地是**唯一真相**：任何操作先改本地、立刻重绘，网络在后台追。
每次往返分两步——**先上传本地改动，再拉取别人的改动**（顺序不能反，反了会覆盖掉还没上传的修改）。

- 只被改过、还没上传的行会被打上 `_dirty` 标记，拉取时跳过它们，所以不会被服务器旧版本覆盖。
- 删掉的行会留一个**墓碑**（记在 `localStorage` 的 `qs.deleted` 里），
  联网失败就下次重试。**没有墓碑，断网时的删除会永远丢失**——因为行已经从本地抹掉，
  再也没有线索知道"它还没被删掉"，下次打开它就又回来了。
- 两边同时改同一条，规则是"最后写入的赢"。冲突时可能丢掉一次修改，对个人清单够用了。

## 8. 想自己改，改这几处

| 想改什么 | 改哪里 |
| --- | --- |
| 配色 | `index.html` 的 `:root{}` 里的 CSS 变量 |
| "还剩几天"变黄 | `dueState()` 里的 `soonMs`（现在是 3 天） |
| 固定时区 | `TZ_OFFSET_HOURS`（现在是 8） |
| 加第四类清单（比如 D 复习） | `CATS` 数组加一项；`supabase.sql` 的 `check (category in (...))` 里加上 `'D'` |

改完重新上传到 GitHub，等一分钟刷新即可（手机可能要下拉刷新，或清一下页面缓存）。

## 9. 排错

| 现象 | 原因 / 处理 |
| --- | --- |
| 打开是登录页，登录报 `Invalid login credentials` | 邮箱密码不对，或者建用户时没勾 Auto Confirm |
| 登录成功但列表一直空、状态显示"同步失败" | 忘跑 `supabase.sql`，或者 URL / anon key 填错 |
| 状态显示"未连接：请检查 Supabase 配置" | `SUPABASE_URL` / `SUPABASE_ANON_KEY` 还有空值 |
| 显示"CDN 没加载上" | 页面打开时不联网。Supabase 的 SDK 是从 CDN 拉的，第一次打开需要联网 |
| 手机上两个浏览器都显示不同数据 | 每个浏览器各有自己的 `localStorage`，各自登录一次即可 |
| 换手机 / 清了浏览器数据要重新登录 | 正常。密码填一次就好，别把密码忘了 |

## 10. 已经知道但暂时没做的

按"值不值得"排个序，以后想做哪个告诉我：

1. **离线模式**：断网时能改、联网自动补传（现在断网会提示，不会丢数据但也不能改）。
2. **拖拽排序**：需要加一个 `sort_order` 字段，用手动顺序替代现在的自动排序。
3. **提醒**：Web 通知（PWA 能力有限），或者干脆接个推送到手机的服务。
4. **重复任务**：比如"每周三交作业"，需要 `recurrence` 规则。
5. **撤销**：删除后给一个"撤销"按钮，比 `confirm` 弹窗友善得多。
